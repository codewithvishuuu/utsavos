# Development

## Prerequisites

- Python 3.11 (3.12 not tested; `requires-python` is `>=3.11,<3.13`)
- Node 24 and pnpm 9
- Docker Desktop (PostgreSQL 16)
- Ollama with `gemma4:e2b` only if working on local AI
- A Gemini API key only if working on the cloud provider

## First run

```powershell
docker compose up -d db

cd apps/api
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev]"
Copy-Item ../../.env.example .env
.\.venv\Scripts\python -m alembic upgrade head
.\.venv\Scripts\python -m uvicorn utsavos.main:app --reload --app-dir src

cd ../web
pnpm install
pnpm dev
```

`--app-dir src` is required because the package is not installed into the venv during normal development. Alternatively `pip install -e .`.

## Rules that keep the design honest

1. **No money or feasibility logic in routers, React or prompts.** Put it in `domain/planning.py` and call it.
2. **No database session in the domain.** Build a `Snapshot` in the service.
3. **Integer paise only.** Do not introduce floats, decimals-in-rupees, or rounding to whole rupees.
4. **Guest count changes go through proposals.** The `PATCH` guard exists for a reason; do not bypass it in the UI.
5. **AI output is display-only.** Never write a model result to an event. Never let a model compute a total.
6. **Tests use real PostgreSQL.** Do not add a SQLite fallback.
7. **New limits and shortcuts get a `shortcut:` comment** explaining the ceiling and the upgrade trigger.
8. **404 for other users' resources**, not 403.

## Adding an endpoint

1. Add the Pydantic model to `schemas.py` with bounds.
2. Add the route to the relevant router. Authenticated writes use `get_current_user` and the router already applies `csrf_guard`.
3. Scope every query through `owned_event` or `user_id`.
4. Put business rules in the service/domain, not the route.
5. Add an integration test with a second user where ownership matters.
6. Update `docs/API.md`.

## Migrations

```powershell
cd apps/api
.\.venv\Scripts\python -m alembic revision --autogenerate -m "describe change"
.\.venv\Scripts\python -m alembic upgrade head
```

Review autogenerated SQL. The first migration intentionally uses metadata; later migrations should use explicit operations. Never edit an applied migration.

## Frontend

- TypeScript strict, no `any` unless unavoidable.
- `api/client.ts` is the only place that calls `fetch`; it attaches the CSRF header from the cookie.
- Money formatting lives in `lib/format.ts` and is unit-tested; budget semantics are asserted in `components/BudgetSummary.test.tsx`.
- The Playwright E2E builds the SPA, starts the API on :8000 and needs the local PostgreSQL database plus Chromium, Firefox and WebKit (`pnpm exec playwright install`).
- The public landing page lives in `src/routes/Landing.tsx`; it uses existing brand icons, system fonts and inline SVG art, with no external assets.
- The dashboard and Studio visual design remain deferred; do not pretend they are complete.

## Debugging

- `/api/docs` is available in development and test only.
- `GET /readyz` shows database readiness: connectivity, expected schema and migration head.
- `X-Request-ID` is returned on every response and included in error bodies. An inbound value is accepted only when it is 1–128 characters, starts with a letter or digit, and contains only `A-Z a-z 0-9 . _ : -`; otherwise the API generates a new id. It is correlation only, never authentication. The default log format prints `request_id=...`, `LOG_LEVEL` controls verbosity, and completion logs contain method, path, status and duration but never query strings, headers, cookies or bodies. Library HTTP client logs are held at `WARNING` so outbound URLs are not emitted at `INFO`.
- If Ollama returns empty content, confirm `think=false`; the provider sets it.
- If cookies do not stick in a local HTTP run, make sure `APP_ENV=development`; production rejects insecure cookies and requires HTTPS.

## Environment

`.env` is gitignored. Copy `.env.example` to `apps/api/.env` for host development or to the repository root `.env` for compose. Never commit a real secret. Production startup rejects the development placeholder.

## CI

`.github/workflows/ci.yml` runs backend lint/type/migration/tests against a PostgreSQL service and frontend install/test/build. It has not been run on GitHub from this workspace; run the same commands locally before pushing. Playwright E2E is local only.
